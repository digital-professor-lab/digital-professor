Digital Professor / Week 3 executive update
Course evidence retrieval pilot complete

What we built

From course materials to cited evidence.

This week, I built and tested a way to find cited evidence across two courses before an AI model answers.

The flow

From course resources to measured retrieval

01 · Resource framework

Three source roles

I organized the syllabus, course context, and textbook-based reference for each of our two courses. I kept them separate so the system knows what defines the course, what shows the teaching sequence, and where to find more detail.

Syllabus

It defines learning goals and course scope.

Course context

It shows the order of topics and prerequisites.

Textbook reference

It adds detail from AI-prepared course breakdowns.

02 · Structured knowledge

Four linked layers

I built a knowledge map like a library catalog, so every idea has an address: course, document, section, and original passage. I linked each AI-extracted concept card to its source, so a card match can lead us back to evidence we can cite.

1 · Course

Which class owns this idea?

2 · Document

Which source did it come from?

3 · Section

Which chapter covers it?

4 · Passage

Where is the exact text we can cite?

03 · Hugging Face models

Two semantic indexes

I used two existing Hugging Face models, BGE and Qwen3, to turn the same concept cards and passages into searchable vectors. My goal was to compare how well each model finds related ideas in our own course materials.

Same input

Both models encoded the same 476 cards and passage segments.

Two indexes

I stored separate indexes in PostgreSQL with pgvector for a fair comparison.

Source links

Each vector stays linked to its course and original passage.

04 · Hybrid search

Find, merge, filter

I built a hybrid search that combines meaning-based and keyword matches, even when a student does not name a course. After checking course scope, it returns up to six passages with file and line numbers for the answer model.

Meaning

Vectors find ideas close to the question in meaning.

Keywords

Keywords catch exact terms; concept cards lead back to passages.

Evidence

Scope checks leave up to six passages with file and line citations.

05 · Evaluation framework

How I judged retrieval

I built an evaluation framework to check whether retrieval finds all the evidence a question needs, not just something related. I tested 50 questions across five setups, including easy, medium, hard, and missing-answer cases.

Complete evidence

I check every passage needed for a full answer.

Trustworthy sources

I verify the course, scope, and citation lines.

Hard cases

I include difficult and missing-answer questions.

How we tested

I tested 50 questions in five setups

25 + 25I used 25 questions from each course.
8 / 9 / 8Each course had 8 basic, 9 intermediate, and 8 advanced questions.
5 waysI compared each model alone, each with keywords, and both together.

Of the 50 questions, 46 had supporting evidence in our materials. Four tested course scope or missing information. This measures retrieval, not final AI answers.

87%40 of 46 answerable questions

Retrieval result · current combined flow

Complete evidence for 40 of 46 questions

  • What worked: The right course appeared in the top three for all 46 answerable questions, and every citation matched its source.
  • Why six fell short: We found the needed passages at first, but our final rule kept only two passages per file. That left evidence out of the final six.
  • What I tested next: Allowing four passages per file recovered four of those six in a diagnostic run. Simpler model setups also reached 41/46, so we will compare the options again.
  • What remains: When the material has no answer, the system still returns related passages. We need an insufficient-evidence check and instructor review before student use.
