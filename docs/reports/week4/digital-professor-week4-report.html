Digital Professor / Week 4 update
Retrieval schema redesign · 2 October 2026

This week's work · input & output schemas

Redesigning the retrieval system's schema.

Clear structures for stored knowledge, retrieved evidence, and the search report — so downstream steps know what they receive.

The flow

The retrieval flow

Select a card for its key design or result.

01 · Resource framework

Source roles stay explicit

Six files cover Calculus I and Number Theory I. Each file keeps its course and source type.

02 · Structured knowledge

Every match has an address

221 passages and 216 concept cards link back to their source lines. Every match has an address.

03 · Hugging Face models

Two models, one shared input

On the original test, BGE alone covered 38/46 questions and Qwen3 covered 41/46; both plus keywords covered 40/46. Two models add different candidates, but combining them does not automatically improve coverage.

04 · Hybrid search

A bounded evidence handoff

Meaning and keywords work together to select up to six passages. Scope checks decide whether to search, stop, or ask for clarification.

05 · Evaluation framework

Inspect each question and source

The current run covers all expected evidence for 46/46 answerable questions. Four scope and missing-source cases also return the expected decisions.

01 · Input schema

Stable knowledge

Give the SQL knowledge base a consistent structure.

02 · Evidence schema

Usable LLM input

Identify each hit and pass its cited text to the LLM.

03 · Report schema

Evaluation & validation

Check search quality and decide whether to retrieve again.

Input · knowledge schema

Keep the knowledge base consistent.

Store each source, section, and passage in linked SQL tables. A stable structure makes the knowledge easy to find and reuse.

Output · retrieved evidence

Give the LLM evidence it can identify.

Each hit carries the original text, source location, and search signals. Downstream code can read it consistently and pass cited evidence to the LLM.

Schema · all fields

Field : what it means

Scroll to see the complete definition.

citation :
Short marker such as S1, used in the assembled context.
passage_id :
Stable identifier for the source passage; used to link and merge hits.
course_id :
Machine-readable course ID and display name.
course_name :
Machine-readable course ID and display name.
source_type :
Syllabus, course context, or textbook-reference role.
filename :
Source file name and the preserved local snapshot location.
snapshot_path :
Source file name and the preserved local snapshot location.
section_path :
Chapter and section hierarchy.
line_start :
Start and end lines in the source LaTeX file, not textbook page numbers.
line_end :
Start and end lines in the source LaTeX file, not textbook page numbers.
scope_status :
Whether the passage belongs to the pilot or an opt-in scope.
review_status :
Source review state; the current supplied files are unverified.
known_issues :
Recorded unresolved issues attached to this source span.
score :
Fusion ranking score. It is not an answer-confidence probability.
selection_score :
Selection value after focused reranking or the soft file preference; also not confidence.
selection_reason :
Selected through query coverage or ordinary ranking.
signals :
Search channels that matched, such as BGE, Qwen3, or keywords.
matched_record_ids :
Concept-card or passage-segment records mapped to this passage.
query_matches :
Focused subqueries that reserved evidence from this passage.
raw_latex :
The original source excerpt. Returned in full, without a newly generated summary.

Output · retrieval report

Let downstream steps check the search.

Record the question, decision, evidence, and search process. Evaluation and validation can use this report to judge retrieval quality and decide whether to search again.

Schema · all fields

Field : what it means

Scroll to see the complete definition.

schema_version :
Version of the output contract: 1.1.
question :
The original student or instructor question.
status :
found, not_found, or needs_clarification.
message :
Short readable label for an empty or clarification outcome.
not_found_reason :
Specific reason for Not found; null for found or clarification.
scope_assessment :
Structured request-scope and source-availability decision; expand below.
evidence_assessment :
Currently records not_assessed or no_selected_evidence, plus a next action.
filters :
Course filter, allowed scopes, and whether known-issue passages are included.
models :
The embedding models used by this request.
retrieval_queries :
Original question plus any focused subqueries.
use_lexical :
Whether keyword-search channels are enabled.
max_per_document :
Per-file preference (default four) and soft/hard selection mode.
document_limit_mode :
Per-file preference (default four) and soft/hard selection mode.
results :
Ordered array of the structured hit records in Output 01.
context :
Those source excerpts assembled with citation markers and source metadata.
channel_candidate_counts :
Candidate record counts from the original-query search channels.
facet_candidate_counts :
Candidate channel counts for each focused subquery, when used.
total_distinct_candidate_passages :
Distinct candidate passages in the merged selection pool.
selection_skip_reasons :
Counts skipped for broad-keyword-only support, a hard file cap, or budget.
raw_excerpt_characters :
Total characters of selected original excerpts; excludes added citation headers.
retrieval_seconds :
Search, selection, and assembly time; excludes question embedding and model loading.
scope_assessment.policy_version :
Version of the request decision rules.
scope_assessment.decision :
retrieve, not_found, or needs_clarification.
scope_assessment.category :
Within scope, out of scope, mixed/ambiguous scope, filter conflict, or source unavailable.
scope_assessment.reason_code :
Machine-readable explanation of a stop or clarification decision.
scope_assessment.requested_scopes :
What the question explicitly requests versus what this search permits.
scope_assessment.allowed_scopes :
What the question explicitly requests versus what this search permits.
scope_assessment.required_source_types :
Needed source roles versus those in the selected course catalog.
scope_assessment.available_source_types :
Needed source roles versus those in the selected course catalog.
scope_assessment.matched_rules :
Rule identifiers and matched question text, making the decision inspectable.
scope_assessment.next_action :
Retrieve, clarify scope, change/confirm scope, or request missing sources.
scope_assessment.explanation :
Readable explanation of the decision; not a model-confidence score.
filters.course_id :
Optional course restriction; null searches both courses.
filters.allowed_scopes :
Scope labels enabled for the request.
filters.include_flagged :
Whether unresolved known issues are allowed.
evidence_assessment.status :
not_assessed when semantic sufficiency has not been judged; no_selected_evidence when selection is empty.
evidence_assessment.next_action :
Review evidence, adjust the context budget, revise the query/sources, or follow the scope decision.
selection_skip_reasons.broad_lexical_only :
Candidate supported only by broad keyword search.
selection_skip_reasons.document_cap :
Candidate excluded by a hard file cap; a soft preference does not discard for this reason.
selection_skip_reasons.context_budget :
Candidate excerpt would exceed the remaining character budget.
scope_assessment.matched_rules[].rule :
Which decision rule matched.
scope_assessment.matched_rules[].matched_text :
Question text matched by that rule.
