04 / Additional investigation

Outlined a textbook-to-Wiki RAG pipeline

Extended the Week 1 research beyond model selection to define a practical way to convert a syllabus and textbook into a traceable course knowledge base for retrieval.

Microsoft SkillOpt ↗

What it is: A framework that improves reusable natural-language agent skills through repeated rollout, reflection, editing, and validation—without changing the base model’s weights.

Potential use here: Start with a textbook-extraction skill, score its output against reviewed examples, and later use a SkillOpt-style loop to improve its instructions and consistency.

Wiki.js · Wiki knowledge base ↗

What it is: An open-source Wiki platform for organizing searchable, linked, and maintainable documentation.

Potential use here: Store course concepts as readable Wiki pages with chapter, page, and source metadata. The Wiki is the organized content layer; a search/vector index would make those pages available to RAG.

Proposed entry point

Step What we would do Output / validation
1 · Define the schema Use the syllabus as the course map and define a standard Wiki template before processing the full textbook. Module, concept, definition, objective, prerequisite, formula/example, chapter, page, and source text.
2 · Build the extraction skill Extract important concepts, formulas, examples, and relationships from each textbook section, while retaining provenance and flagging uncertain output. Compare extracted fields with a small human-reviewed gold set; optimize the skill only after this baseline exists.
3 · Ingest chapter by chapter Write approved entries into a concise knowledge layer and keep the original textbook passage in an evidence layer. Every Wiki claim remains linked to its textbook chapter/page; missing summaries can fall back to source evidence.
4 · Connect and test RAG Index the Wiki content, retrieve relevant entries for course questions, and require the model to answer from retrieved evidence with citations. Measure passage Recall@k, source/citation correctness, answer completeness, unsupported-claim rate, and abstention when evidence is missing.
Recommended MVP: One syllabus + one textbook + one or two chapters + 20–30 reviewed test questions. First validate extraction and retrieval separately; then evaluate whether the final answer is complete and fully grounded in the cited course material.

Important distinction: SkillOpt is a possible optimization method, not the ingestion system itself. A Wiki organizes and governs the course content, but it does not automatically provide semantic RAG; the pages still need chunking, indexing, retrieval, and evaluation. This is a proposed approach and has not yet been implemented.

Model routing as a next direction

Microsoft · Azure AI Foundry Model Router ↗

Routes each prompt to a suitable model based on task complexity, quality needs, and cost.

AWS · Bedrock Intelligent Prompt Routing ↗

Routes simple requests to smaller models and difficult requests to stronger models within a model family.

Proposed sequence: First fix a baseline and a RAG / prompt evaluation framework, then benchmark the mainstream candidates and select a main model. After that, analyze its failure cases and decide whether the product needs a model-selection layer.

Why consider routing later? Microsoft Model Router and AWS Intelligent Prompt Routing address the same practical problem: no single model is always best on quality, speed, and cost. They can send simple requests to a smaller, faster model and reserve stronger models for difficult, visual, or long-context cases. We should consider this only after the baseline shows a stable weakness, latency issue, or avoidable cost in the main model.
